# 開發環境建立

給接手這個專案的人（或 AI agent）。從零到能跑起全部服務並通過測試。

- 對象：macOS / Linux
- 預估時間：40～60 分鐘（多數時間在等 `cargo build`）
- 最後更新：2026-09-17

---

## 1. 這是什麼專案

**台灣製造業中小企業的 AI 時代流程引擎。**

定位：*不換 ERP，把 Excel／Email／LINE 上的簽核變成有 ERP 寫回、可稽核的正式流程。*

客戶不需要丟掉現有的 ERP。這套系統管的是「這張單走到誰手上、誰批過、
何時批的」，簽核完把結果寫回 ERP。

### 1.1 技術組成

| 元件 | 技術 | 職責 |
|------|------|------|
| `server/` | Rust + Axum + SQLx | API、租戶隔離、授權 |
| `web/` | Vue 3 + TypeScript + Tailwind | 設計器與操作介面 |
| `python-ai/` | Python + Temporal SDK | 流程解譯與 Worker |
| `pdfme/` | Node + pdfme | 單據渲染 |
| PostgreSQL 17 | — | 資料庫，啟用 RLS |
| Temporal 1.25.2 | Docker | 流程引擎 |

### 1.2 兩個必須先懂的設計

接手前先讀懂這兩點，否則會寫出有安全漏洞或行為詭異的程式碼。

**租戶隔離靠 Row Level Security，不是靠 WHERE 條件。**

應用程式用 `workflow_app` 這個**非 superuser** 角色連線，
每筆查詢都受 RLS policy 約束。取得連線的唯一入口是
`db.tenant_tx(tenant_id)`，它會設定 `app.tenant_id`。

繞過它（例如直接用 pool 查詢）等於關掉租戶隔離。程式碼裡只有
登入流程合法繞過一次（登入時還不知道租戶），且立刻切回。

實際效果：用 `psql -U workflow_app` 不設 `app.tenant_id` 查任何表都是 0 筆。

**權限的角色清單是三態，不是兩態。**

```jsonc
{ }                    // 鍵不存在 = 不限制，所有人可以
{ "roles": [] }        // 空陣列 = 全部拒絕
{ "roles": ["cfo"] }   // 只有 cfo
```

`[]` 與「鍵不存在」意義相反。合併兩份權限設定時必須用
`patch.workflow ?? base.workflow` 而非展開合併——
展開會讓「改為不限制」（刪掉鍵）變成無效的空操作。

## 4. 資料庫

### 4.1 啟動 PostgreSQL

```bash
brew services start postgresql@17
```

### 4.2 建立資料庫與角色

```bash
createdb workflow
```

`server/migrations/0000_roles.sql` 會建立 `workflow_app` 角色。
它刻意是**非 superuser**——superuser 會繞過 RLS，
用它跑等於整套租戶隔離失效。

### 4.3 執行遷移

```bash
for f in server/migrations/0*.sql; do
  psql -d workflow -f "$f"
done
```

六個檔案依序建立角色、租戶與身分、表單定義、稽核、流程定義、流程實例。

### 4.4 驗證 RLS

```bash
./server/migrations/verify_rls.sh
```

九項檢查，全部通過才算設定正確。**任何一項失敗都不要繼續**——
RLS 沒生效代表租戶資料會互相看見。

## 8. 啟動

```bash
./start_service.sh
```

依相依順序啟動六個服務。**順序不能亂**：

- Temporal 必須早於 Rust API——API 啟動時連一次 Temporal，
  連不上就以 `temporal=None` 執行，流程端點全回 503 且不會自己重連
- Rust API 必須早於 Worker——Worker 啟動時就會連 internal API

其他指令：

```bash
./start_service.sh --status      # 只看狀態
./stop_service.sh                # 停止（保留 PostgreSQL 與 Docker）
./stop_service.sh --keep-temporal  # 保留 Temporal，重啟較快
```

啟動後：

| 服務 | 位址 |
|------|------|
| 前端 | http://localhost:3040 |
| Temporal UI | http://localhost:8080 |
| API | http://localhost:3001 |

日誌在 `.logs/`。

## 10. 開發約定

### 10.1 測試

本專案採 TDD，目標覆蓋率 80%。實際做法：

1. 先寫測試，確認 RED
2. 實作到 GREEN
3. 每個功能都要有 client→server API 單元測試與 E2E 測試
4. 測試報告寫到 `docs/測試報告/YYYYMM/`，**E2E 要附截圖**

測試分五層：

| 層 | 內容 | 位置 |
|----|------|------|
| L1 | 單元 | 各語言的測試目錄 |
| L2 | 契約 | `server/crates/*/tests/` |
| L3 | client API（MSW） | `web/tests/api/` |
| L4 | 整合 | `server/crates/http-public/tests/` |
| L5 | E2E（Playwright） | `web/e2e/` |

### 10.2 語言

- 程式碼註解、文件、commit message 一律**繁體中文**
- 註解寫「為什麼」不寫「做什麼」
- 技術名詞保持原文（`RLS`、`Temporal`、`resolver`）

### 10.3 Git

- Conventional commits：`feat:` `fix:` `refactor:` `docs:` `test:` `chore:`
- **未經指示不要自行 commit 或建立分支**

## 11. 這個環境踩過的坑

真實遇過並修正的，接手時別重蹈覆轍。

### 11.1 macOS 的 bash 3.2

兩個陷阱，都在 `set -u` 下才會觸發：

```bash
# 同一個 local 敘述引用前面剛宣告的變數 → unbound variable
local name=$1 file="$DIR/$name.pid"        # 壞
local name=$1; local file="$DIR/$name.pid" # 好

# 變數緊貼全形字元 → 位元組被併進變數名
echo "$port）"    # 壞，變數名變成 port+亂碼
echo "${port}）"  # 好
```

### 11.2 Vue 的 v-model 與動態 type

```vue
<!-- 壞：Vue 無法在編譯期決定 v-model 實作 -->
<input v-model="x" :type="dynamicType" />

<!-- 好：分成兩個靜態分支 -->
<input v-if="isNumber" v-model="x" type="number" />
<input v-else v-model="x" type="text" />
```

另外，`type="number"` 的 input 搭 `v-model`，**值進來是 number 不是 string**。
假設它是字串而呼叫 `.trim()` 會拋 TypeError——而且如果那段程式在
try 之外，例外往上冒，整個動作無聲中止，畫面上什麼都不會顯示。

### 11.3 業務資料的巢狀層級

流程定義的條件式與 resolver 讀的是巢狀路徑：

```jsonc
"expression": "quotation.discount_rate > 0.15"
"resolver": { "type": "external_contacts", "path": "quotation.customer_contact_ids" }
```

送 `{ "discount_rate": 0.2 }`（頂層）會有兩種後果：

- **條件式取不到值 → 當成 false**，靜默跳過該段簽核，沒有任何錯誤
- **resolver 取不到 → NoParticipants**，整個流程 FAILED

第一種特別危險：高折扣的報價單會不經財務就發出去，而沒有人會發現。

### 11.4 表單定義的型別名稱不只一種

`data.type` 可能是 `decimal`、`number`、`integer`。
只認其中一種的話，其他型別會靜默送出字串，
而條件式拿字串做大小比較的結果不可預期。

### 11.5 Temporal 以 workflow_id 去重

重複的 `business_key` 會讓 API 回 201 但實際沒有新的執行——
`temporal workflow describe` 看到的是舊的那次。

測試時務必用帶時間戳的單號。

### 11.6 測試通過不代表截圖正確

`expect(page).toHaveURL(...)` 會重試到通過，`page.screenshot()` 卻是立即執行。
URL 已經變了而畫面還停在上一頁，截圖就是錯的。

截圖前先 `await page.waitForLoadState('networkidle')`。

### 11.7 型別錯誤不要用 as unknown as 壓掉

曾經有一段 pdfme 的分頁保護邏輯，因為型別不符而用
`as unknown as` 強制轉型。結果是那段程式**從未被執行**，
而所有測試依然全綠——測試測的是純函數本身，不是渲染路徑。

型別錯誤原本就在警告「這個切點不存在」。

## 12. 疑難排解

| 症狀 | 原因與處理 |
|------|-----------|
| 查詢一律 0 筆 | 用 `workflow_app` 但沒設 `app.tenant_id`，RLS 擋掉。跨租戶查詢用 superuser |
| 流程端點回 503 | Temporal 沒起，或 API 在 Temporal 之前啟動。重啟 API |
| 流程停在第一個節點 | Worker 沒跑，或 `INTERNAL_API_TOKEN` 不一致 |
| 流程 FAILED / NoParticipants | 業務資料的巢狀層級錯了，見 11.3 |
| `npm install` 失敗（edgesOut） | pdfme 的 vitest 版本，見 6.4 |
| E2E 逾時在第二次登入 | 已登入時 guard 會把 `/login` 導回首頁。換帳號前先清 session |
