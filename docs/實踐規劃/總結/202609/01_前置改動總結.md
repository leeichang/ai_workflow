## 2. 規劃階段最重要的發現

**WF-E012 的路徑真相來源不能是表單定義。**

兩份交接文件都假設「檢查路徑是否存在於業務物件的結構定義中」，
但沒有說那份結構定義從哪來。查證後發現資料庫根本沒有這樣的表，
路徑只在表單欄位的 `data.path` 宣告。

而實測顯示：**同一個 `business_object` 的多張表單，路徑詞彙互不相容。**

`quotation` 的兩張表單，13 條路徑只有 3 條重疊：

| 概念 | `seed.sh` 的表單 | fixture 的表單 |
|---|---|---|
| 總計 | `quotation.total_amount` | `quotation.total` |
| 內部備註 | `internal_notes`（複數）| `internal_note`（單數）|
| 毛利率 | `gross_margin` | `margin_rate` |

**取聯集會讓 `internal_note` 與 `internal_notes` 都合法——等於不檢查拼錯字，
而拼錯字正是 WF-E012 要擋的東西。**

因此新增 `schemas/business-objects/*.json` 作為獨立於表單的真相來源，
並刻意不收錄舊名稱。

這個發現同時影響 AI 產生器：若讓 AI 從表單反推可用欄位，
它會同時看到 `total` 與 `total_amount` 而不知道該用哪個。

## 5. 過程中修正的認知

### 5.1 一份先前的陳述需要更正

規劃初稿寫「`quotation.customer_contact_ids` 在表單沒有宣告，
是執行期從 `input` 帶進來的」。

**那是錯的。** `schemas/fixtures/quotation_form_v1.json` 有宣告它；
沒有宣告的是 `server/seed.sh` 內嵌的另一張表單。

更正後的事實更有說服力——問題不是「表單漏了執行期欄位」，
而是「同一個業務物件有兩套不相容的詞彙」。規劃文件已更正。

### 5.2 測試先寫確實抓到東西

`string_literals_are_not_paths` 第一次跑是紅的。
檢查後發現**實作是對的**（`'TWD.dollar'` 確實被正確排除），
是測試自己用了未宣告的 `quotation.currency`。

若先寫實作再補測試，很可能會反過來去改實作。

## 6. 給下一棒的建議

### 6.1 先補 P3 再進 S0

P3 會改 `workflow_instance` 的 schema 與建立實例的寫入點。
S0 流程監控要顯示「當時那版表單」，兩者相接。
先做 P3 可以避免 S0 寫到一半回頭改。

### 6.2 業務物件定義漏登記會靜默失去保護

`known_paths` 為空集合代表「不檢查」（沿用 `known_roles` 的既有慣例）。
目前只有 `quotation` 與 `purchase_request` 有定義，
其他業務物件等於沒有 E012 保護。

`business_object.rs` 已提供 `is_known()` 供明確性檢查，
但發布路徑尚未使用。**建議在 S0 或 AI 產生器階段補上
「未定義的業務物件要明確警告」**，否則新增業務物件時會安靜地少一層防護。

### 6.3 `rtk` hook 會弄壞 cargo

全域 `rtk` hook 把 `cargo` 改寫成 `rtk cargo`，但只佔住程序不 spawn cargo，
留下 stale lock 讓後續 build deadlock，且 `ps | grep` 被過濾成空的。

**繞法**：絕對路徑 `~/.cargo/bin/cargo`。
同一個 hook 也吃掉 vitest/playwright 的輸出，要改讀 JSON report
或 `~/Library/Application Support/rtk/tee/*.log`。

這與程式碼無關，但會浪費大量時間。

### 6.4 修 `auth-navigation` 的競態時不要只加 timeout

「切換帳號後顯示對應的人與角色」間歇性失敗，
症狀是 `user-name` 元素查不到。

**加長 timeout 只會把競態藏起來。** 應該等一個明確的就緒訊號，
或在測試間顯式清除 session。交接手冊 §12 已記錄同類症狀
（「已登入時 guard 會把 `/login` 導回首頁，換帳號前先清 session」）。

### 6.5 環境與手冊的三處差異

| 項目 | 手冊 | 實際 |
|---|---|---|
| PostgreSQL | 17 | **16.13**（migration 與 RLS 九項檢查全過）|
| seed 順序 | §7 seed → §8 啟動 | **相反**，seed 會 curl 打 API |
| seed 內容 | 含「簽核流程定義」 | **不含**，`quotation_approval` 要另外註冊 |

最後一項不補的話，`task-approval.spec.ts` 的 6 個測試會全部回 404。
