## 2. 三個需要決定的事

### 2.1 「誰該看得到全部流程」是政策決定

流程監控目前寫死只有 `admin` 不設限，其他人看得到
「自己發起的」＋「自己有待辦的」。

刻意**不**把 `approver`、`finance_manager` 放行：
那些角色是「會簽到某些單」，不是「該看到全部單」。

**但營運上主管可能需要看團隊的單。** 這是政策不是技術，
需要有人決定。若要放行，建議定義一個明確的
`process_monitor` 角色，而不是把既有的簽核角色拿來兼差。

### 2.2 demo 租戶的 `sales_director` 掛 0 人

時間快轉抓到的：`manager_approval` 設 `P2D` / `ESCALATE` 到
`sales_director`，但那個角色**一個人都沒有**。
逾時加簽在正式環境會靜默不發生（Worker 只留一行 WARNING）。

```
demo 租戶角色人數
  viewer 0 · sales_director 0 · designer 1 · admin 1
  finance_manager 1 · cfo 1 · requester 3 · approver 3
```

是資料問題不是程式問題，但它示範了模擬的價值——
**模擬在驗證 resolver 設定對不對，而這個設定是錯的**。

順帶一提：「解析不到加簽對象就繼續等待」這個行為本身也值得討論。
目前是靜默降級，只有 Worker log 看得到。

### 2.3 種子表單沒有角色限制欄位

`quotation_form` 沒有任何 `readable_roles`，所以
**HIDDEN 這條路徑沒有在實機上觀察過**（單元測試有蓋）。

要真的驗證「這個人看不到成本」，種子需要一張帶角色限制的表單。
建議在 `quotation_form` 加一個 `unit_cost` 之類的欄位限定
`finance_manager`、`cfo` 可讀——同時也讓模擬的示範更有說服力。
