## 3. 建立新表單

按右上角「建立表單」。

![建立表單對話框](screenshots/01-表單/06-建立表單對話框.png)

三個欄位：

| 欄位 | 說明 |
|------|------|
| **表單名稱** | 給人看的名稱，例如「員工基本資料」。之後可以改 |
| **表單代碼** | 系統用的識別碼，例如 `employee_form`。**建立後不能改** |
| 業務物件 | 這張表單管的是什麼資料。留空則與表單代碼相同 |

![填寫表單資訊](screenshots/01-表單/07-填寫表單資訊.png)

**表單代碼的限制**：只能用小寫英文、數字與底線，且要以英文開頭。

> 為什麼不能改？表單代碼會變成系統網址的一部分，也是資料庫關聯的依據。
> 改了會讓既有的單據找不到自己的表單定義。

**業務物件是什麼？** 它決定流程的條件式可以引用哪些資料。
業務物件填 `employee` 時，流程才能寫 `employee.salary > 50000`
這種判斷。同一個業務物件可以有多張表單（例如「員工基本資料」與
「員工異動申請」），它們共用同一套欄位名稱。

按「建立並開始設計」。

![元件庫](screenshots/01-表單/09-元件庫.png)

| 元件 | 用途 |
|------|------|

| 多行文字 | 備註、說明 |

**進階欄位**

| 元件 | 用途 |

## 6. 加入欄位

**點一下元件庫的項目就會加入畫布**，不需要拖曳。

點「單行文字」。

![加入單行文字欄位](screenshots/01-表單/10-加入單行文字欄位.png)

新欄位會自動選取，右側出現屬性面板。

### 6.1 基本分頁

![設定欄位名稱](screenshots/01-表單/11-設定欄位名稱.png)

| 屬性 | 說明 |
|------|------|
| **欄位標籤** | 使用者看到的名稱，例如「姓名」 |
| 提示文字 | 欄位空白時顯示的灰字 |
| 輔助說明文字 | 欄位下方的小字說明 |
| 欄位寬度 | 佔幾格。12 格為滿版 |
| **客戶 Portal 可見** | 關掉的話外部客戶看不到這個欄位 |

> **客戶 Portal 可見**這個開關控制外部人員看不看得到這個欄位。
> 員工表單通常不會給外部看，但薪資、考績這類欄位仍建議關掉——
> 表單日後若被其他流程引用，關掉比事後補救安全。
>
> 這個開關在需要送給外部的單據上更關鍵。例如報價單的成本與毛利率
> 一定要關，否則等於把底價告訴客戶。

### 6.2 資料分頁

![設定資料路徑](screenshots/01-表單/12-設定資料路徑.png)

**資料路徑**決定這個欄位的值存到哪裡。

格式是 `業務物件.欄位名`，例如 `employee.name`。

規則：

- 用小寫英文與底線，例如 `hire_date` 不要寫 `hireDate`
- 同一個概念在不同表單要用**同一個名字**。「總計」一張表單叫 `total`
  另一張叫 `total_amount` 的話，流程的條件式會在其中一張上失效
- 巢狀路徑用點分隔，例如 `customer.contact_email`

> 這一步容易被略過，但它決定了流程能不能判斷這張單。
> 條件式 `employee.salary > 50000` 能成立的前提是有欄位宣告了
> `employee.salary` 這條路徑。

## 8. 明細表格

點進階欄位的「明細表格」。

![加入明細表格](screenshots/01-表單/15-加入明細表格.png)

這裡加的是「工作經歷」。

明細表格是「一張單有多筆資料」的欄位。例如：

```
員工基本資料（一張）
  ├── 工作經歷 1：台積電  製程工程師  2018-2021
  ├── 工作經歷 2：聯電    設備工程師  2021-2023
  └── 工作經歷 3：日月光  課長        2023-2025
```

表格的每一欄要各自設定（公司、職稱、起訖日…）。
與一般欄位不同的是，它的資料路徑指向一個陣列。

> 截圖中表格的欄位還是預設的「品名／數量／金額」。
> 那是元件的預設欄位，要在「資料」分頁逐欄改成工作經歷需要的內容。

## 9. 欄位規則

切到「規則」分頁。

![欄位規則](screenshots/01-表單/16-欄位規則.png)

| 規則 | 說明 |
|------|------|
| **顯示條件** | 什麼情況下才顯示這個欄位 |
| **唯讀條件** | 什麼情況下不能編輯 |
| **必填條件** | 什麼情況下必須填 |

條件可以引用流程節點，例如：

```
node.id not in ['start', 'revise']
```

意思是「除了填寫與修改階段，其他關卡都唯讀」——
送簽之後金額就不該再被改動。

也可以引用欄位值：

```
employee.employment_type == 'contract'
```

意思是「員工類型是約聘時才顯示」（例如合約到期日）。

## 10. 權限預覽

設好權限後，用預覽確認實際效果。按上方「權限預覽」。

![權限預覽](screenshots/01-表單/17-權限預覽.png)

下方出現面板，顯示**每個欄位在特定角色眼中的樣子**：

| 標示 | 意思 |
|------|------|
| 可編輯 | 該角色可以填寫 |
| 唯讀 | 看得到但不能改 |
| 隱藏 | 完全看不到 |

切換角色看不同結果。

![以申請人身分預覽](screenshots/01-表單/18-以申請人身分預覽.png)

> 權限由六條規則依序判定，設計者很難從幾個獨立的設定推出最終結果。
> 預覽直接問系統「這個角色實際會看到什麼」，比自己推可靠。

![儲存草稿](screenshots/01-表單/20-儲存草稿.png)

### 發布

![發布表單](screenshots/01-表單/21-發布表單.png)

發布後這個版本才會生效。

| | 草稿 | 已發布 |
|---|---|---|
| 誰看得到 | 只有設計者 | 所有使用者 |
| 新建的單據 | 不會用到 | 會用到 |
| 可以再改嗎 | 可以 | 要另存新草稿 |

**發布不會影響進行中的單據**——它們仍用送簽當時的版本。

## 常見問題

**表單代碼可以改嗎？**
不能。它是網址與資料關聯的依據。取錯的話只能建一張新的。

**刪掉欄位會影響既有單據嗎？**
已送簽的單據用的是當時的版本，不受影響。但新建的單據就沒有那個欄位了，
而報表如果在查那個欄位會查不到。刪之前先確認沒有流程的條件式在引用它。

**「業務物件」和「表單代碼」有什麼差別？**
表單代碼是「這張表單」，業務物件是「這類資料」。
「員工基本資料」與「員工異動申請」是兩張表單（兩個代碼），
但都在管員工這件事（同一個業務物件 `employee`），
所以共用欄位名稱與流程條件式。

**為什麼新表單一定會有「單號」欄位？**
系統要求表單至少有一個欄位。用單號當預設是因為幾乎每張單據都需要它，
而且它示範了最基本的欄位設定。不需要的話可以刪掉，但要先加別的欄位。
