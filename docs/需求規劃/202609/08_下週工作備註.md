**這五項不是技術問題，開發不該自己決定。**

## 8. 建議的下週排序

這是建議不是決定，實際排程由你定。

### 選項 A：補 AI 產生器（原規劃的主線）

A1～A4 約 3 週，下週能完成 A1 + A2（LLM client 與 Form 產生）。

**為什麼值得先做**：它是這週唯一整組跳過的規劃項目，
而且 [02_AI產生表單與流程交接](../交接手冊/202609/02_AI產生表單與流程交接.md)
已經把設計想清楚了——DSL 已經存在，AI 是 Compiler 不是前端開發者。

**風險**：需要決定 LLM 供應商與金鑰管理。A1 的「假實作」可以先繞過，
但 A2 要真的產生表單就繞不過了。

### 選項 B：補設計器版本化（需求 05）

約 6.5 天，下週剛好做得完。

**為什麼值得先做**：使用者在 09-18 主動提出這個需求並反覆修正細節
（版本語意改了一次、加了編輯鎖定、限制一份草稿），
表示他很在意。而且它**擋住模擬功能的完整體驗**——
文件 §3.7 說編輯頁面要整合模擬，現在兩者是分開的。

**風險**：階段 8 的截圖重產會動到 76 張手冊截圖。

### 選項 C：需求 07 的 P2

約 1～1.5 週。

**為什麼可以延後**：沒有真實客戶系統可驗證，做完也只是對模擬端點
測試過。等有客戶要接 Odoo 再做，收益比較實在。
